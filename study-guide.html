1. 웹 크롤러가 뭔데?

웹 크롤러는 인터넷에서 자동으로 정보를 모아주는 프로그램이에요.

도서관에 가서 신문을 하나하나 읽고, 중요한 기사를 스크랩하는 걸 상상해 보세요.
크롤러는 그 일을 컴퓨터가 자동으로 해주는 거예요.
- 도서관 = 인터넷의 수많은 뉴스 사이트들
- 신문 넘기기 = 웹 페이지에 접속하기
- 기사 오리기 = HTML에서 본문 추출하기
- 스크랩북에 붙이기 = 데이터베이스에 저장하기

구글도 크롤러야?

네! 구글의 Googlebot이 바로 세계 최대의 크롤러예요. 전 세계 웹 페이지를 돌아다니면서 내용을 수집하고, 검색할 때 보여주는 거죠. 우리가 만든 건 한국 뉴스 사이트에 특화된 미니 버전이에요.

2. 이 프로젝트의 핵심 아이디어

보통 크롤러는 사이트마다 코드를 따로 짜요. "조선일보는 이 CSS 선택자로, 한겨레는 저 CSS 선택자로..." 이런 식이죠.

열쇠꾸러미를 상상해 보세요.
보통 크롤러 = 집마다 다른 열쇠가 필요해요. 새 집이 추가되면 새 열쇠를 깎아야 해요.
이 크롤러 = 마스터키예요. 아무 문이든 열 수 있어요!

어떻게 "코드 수정 없이" 가능할까?

비결은 설정 파일(sites.yaml)과 자동 탐지(discover)예요:

  1. 명령어 한 줄로 새 사이트를 등록해요
    python main.py add-site chosun.com
    이게 끝이에요! 코드는 한 글자도 안 고쳐요.
  2. 프로그램이 자동으로 탐지해요 — RSS 주소, 사이트맵 위치, 기사 URL 패턴, 목록 페이지를 스스로 찾아요.
  3. 찾아낸 정보를 sites.yaml에 저장해 두면, 다음 수집 때 자동으로 그 사이트도 포함돼요.
결과: sites.yaml 하나에 244개 뉴스 사이트가 등록되어 있고, python main.py crawl 한 번이면 전부 돌아요!

5. 작동 흐름 5단계

택배 회사에 비유하면:
1. 주소 모으기 = 배달할 집 주소를 수집
2. 필터링 = 이미 배달한 집은 제외, 출입 금지 구역(robots.txt) 확인
3. 물건 받기 = 각 집에 가서 기사(물건)를 가져옴
4. 포장하기 = HTML에서 깔끔하게 본문만 추출
5. 창고에 보관 = 데이터베이스에 저장
  1. 기사 주소 수집 sources.py
    세 가지 방법으로 기사 URL을 찾아요:
    방법설명장점
    RSS 피드사이트가 제공하는 "새 기사 알림" 주소가장 정확, 제목·날짜 포함
    사이트맵구글 같은 검색엔진용 주소 목록모든 기사가 나열됨
    목록 페이지뉴스 사이트 첫 페이지의 링크들RSS/사이트맵 없는 사이트도 OK
    이 세 가지를 순서대로 시도해요. RSS에서 충분히 모았으면 사이트맵은 건너뛰어요.
  2. 중복 체크 & robots.txt pipeline.py
    이미 저장된 기사 URL은 다시 안 가져와요. 그리고 robots.txt라는 파일을 확인해서 "이 페이지는 크롤러가 접근하지 마세요"라고 적혀 있으면 건너뛰어요.
    robots.txt란? 웹사이트 주인이 "크롤러한테 이 페이지는 보여주기 싫어요"라고 적어놓는 규칙 파일이에요. 우리 크롤러는 이걸 존중해요 (예의 바른 크롤러!).
  3. 기사 가져오기 fetch.py browser.py
    대부분의 사이트는 httpx(가벼운 HTTP 요청)로 가져와요. 하지만 SBS처럼 자바스크립트로 기사를 불러오는 사이트는 Playwright(진짜 브라우저)를 써요.
  4. 본문 추출 extract.py
    가져온 HTML에서 기사 제목, 본문, 날짜, 기자 이름을 뽑아내요. 5가지 방법을 순서대로 시도해서 최대한 본문을 살려내요.
  5. 저장 storage.py
    추출한 기사를 SQLite 데이터베이스에 저장해요. 같은 URL이나 같은 내용(text_hash)의 기사는 중복으로 처리해서 안 넣어요.

6. 기사 본문 추출 — 5겹 안전망

뉴스 사이트마다 HTML 구조가 달라서 한 가지 방법으로는 모든 사이트의 본문을 못 뽑아요. 그래서 5가지 방법을 순서대로 시도해요.

자물쇠를 여는 것에 비유하면:
1번 열쇠로 안 열리면 → 2번 열쇠 시도 → 3번... 이런 식으로 5번째 열쇠까지 전부 시도해요. 하나라도 열리면 성공!
#방법원리강점
1 trafilatura (정밀) 광고·메뉴를 제외하고 "기사처럼 생긴 텍스트"만 골라냄 대부분의 뉴스 사이트에서 가장 깔끔
2 JSON-LD HTML 안에 숨겨진 구조화 데이터에서 articleBody를 읽음 사이트가 제공하면 100% 정확
3 trafilatura (재현율) 1번보다 느슨하게 추출 ("좀 더 가져와!") 1번이 너무 적게 뽑았을 때 보완
4 readability-lxml 텍스트가 많이 몰려 있는 영역을 자동 감지 구조가 특이한 사이트에 강함
5 newspaper4k 뉴스 전문 추출 라이브러리 마지막 안전망. 위 4개가 다 실패해도 시도

5가지 중 200자 이상 추출한 첫 번째 결과를 쓰고, 전부 200자 미만이면 가장 긴 결과를 쓰되 80자 미만이면 실패 처리해요.

이게 왜 중요할까?
사이트마다 CSS 선택자를 지정하는 "하드코딩" 방식이면 새 사이트가 추가될 때마다 코드를 고쳐야 해요. 하지만 이 5겹 폴백 시스템 덕분에 대부분의 한국 뉴스 사이트에서 코드 수정 없이 본문을 추출할 수 있어요.

7. Playwright — 자바스크립트 사이트 대응

문제: 빈 페이지?

어떤 사이트(SBS, 뉴스엔 등)는 처음에 빈 HTML을 보내고, 자바스크립트가 실행된 후에야 기사 내용이 화면에 나타나요.

마트에 가서 물건을 달라고 했는데, 직원이 "잠깐만요, 창고에서 가져올게요"라고 해요.
httpx = 직원 말이 끝나기도 전에 가버려서 빈손으로 돌아옴
Playwright = 직원이 물건 가져올 때까지 기다려서 받아옴

Playwright가 뭐야?

진짜 크롬 브라우저를 코드로 조종하는 도구예요. 사람이 브라우저를 열고 페이지를 보는 것과 같은 과정을 프로그램이 자동으로 해요.

# sites.yaml에서 이 사이트는 JS 렌더링이 필요하다고 표시
- name: SBS
  domain: news.sbs.co.kr
  js_render: true        # ← 이 한 줄이면 Playwright를 자동으로 씀!

기사 본문을 언제까지 기다릴까?

16가지 CSS 선택자를 감시하면서 기사 본문 영역이 나타나면 그때 HTML을 가져와요:

# 이런 이름의 요소가 화면에 나타나면 "기사가 로드됐구나!" 판단
article, [class*='article_body'], [class*='news_body'],
[class*='story_body'], [class*='cont_body'], [class*='view_cont'],
[id*='articleBody'], [id*='newsBody'], .article_cont_area ...

Playwright 없이 (httpx)

SBS Biz 기사: 평균 179자
(메타 설명만 겨우 가져옴)

Playwright 적용 후

SBS Biz 기사: 평균 1,449자
(전체 본문 추출 성공!)

주의: Playwright는 진짜 브라우저를 띄우는 거라 httpx보다 느리고 메모리를 많이 써요. 그래서 꼭 필요한 사이트만 js_render: true로 표시해요. 현재 4개 사이트만 적용 중 (SBS, SBS Biz, SBS연예뉴스, 뉴스엔).

8. 스텔스 — 봇 탐지 회피 7가지

뉴스 사이트들은 "이건 사람이 아니라 프로그램이 접속하는 거 같은데?" 하고 의심하면 차단해 버려요. Playwright로 띄운 브라우저도 진짜 사람의 브라우저와 미묘한 차이가 있어서 들킬 수 있어요.

스파이 영화에서 잠입할 때 변장하는 것처럼,
우리 브라우저도 "나 진짜 사람이야!"라고 속이기 위해 7가지 변장을 해요.
#변장 항목왜 필요할까?어떻게?
1 webdriver 숨기기 자동화 브라우저는 navigator.webdriver = true라서 바로 들킴 false로 바꿈
2 chrome.runtime 위장 진짜 크롬에는 있는데 headless에는 비어있음 가짜 객체를 만들어 넣음
3 Permissions 위장 headless는 알림 권한이 'denied' (사람 브라우저는 'default') 'default'로 응답하도록 패치
4 plugins 위장 headless는 플러그인이 0개 (사람은 보통 3개) Chrome PDF Plugin 등 3개 가짜 플러그인
5 languages 위장 한국 사용자답게 보이려면 ['ko-KR', 'ko', 'en-US', 'en']
6 WebGL 위장 headless의 그래픽 카드 정보가 다름 "Google Inc." + ANGLE 렌더러로 위장
7 connection 위장 headless는 네트워크 정보가 비어있음 4G, RTT 50ms 등 일반적인 값 제공

이 7가지를 IIFE(즉시 실행 함수)로 페이지가 로드되기 전에 주입해요. 사이트의 봇 탐지 스크립트보다 먼저 실행되어야 하거든요.

// IIFE = Immediately Invoked Function Expression
// 정의하자마자 바로 실행되는 함수
(() => {
    Object.defineProperty(navigator, 'webdriver', { get: () => false });
    // ... 나머지 6가지도 여기서 실행
})();  // ← 마지막 ()가 "바로 실행해!"라는 뜻

9. 안 막히는 법 — 차단 방어 장치들

뉴스 사이트를 너무 빠르게/많이 접속하면 차단당해요. 그래서 여러 안전장치를 넣었어요:

요청 간격 조절

같은 사이트에 요청할 때 최소 1초 간격을 둬요. robots.txt에 Crawl-delay가 적혀 있으면 그 값을 따라요 (최대 10초).

User-Agent 위장

요청 헤더에 Chrome 131 브라우저인 척하는 User-Agent를 넣어요. "파이썬 프로그램입니다"라고 솔직히 말하면 바로 차단!

차단 감지 & 즉시 중단

403, 429 응답이나 CAPTCHA 페이지(Cloudflare, DataDome, PerimeterX)가 오면 그 사이트에 즉시 요청을 멈춰요.

24시간 쿨다운

차단당한 사이트는 DB에 기록하고, 24시간 동안 다시 접속 안 해요. 다음 실행 때도 이 기록을 확인해서 건너뛰어요.

연속 오류 → 포기

한 사이트에서 네트워크 오류가 연달아 나면 "서버가 죽었구나" 판단하고 그 사이트는 포기해요.

시간 예산

한 사이트에 최대 240초(4분)만 투자해요. 느린 사이트 때문에 전체 수집이 멈추지 않도록요.

결과: 244개 사이트를 동시에 수집해도 현재 차단된 사이트는 0개!

10. Common Crawl — 인터넷 도서관

인터넷 전체를 도서관처럼 보관해 둔 곳이 있어요.
Common Crawl이라는 비영리 단체가 매달 수십억 개의 웹 페이지를 수집해서 누구나 무료로 열람할 수 있게 공개해요.

우리 크롤러가 직접 접속하면 차단당하는 사이트도, Common Crawl에 이미 저장된 과거 버전이 있으면 그걸 가져오면 차단 걱정이 없어요!

작동 방식

  1. CC-INDEX API로 "이 도메인의 기사가 있나?" 검색
    python main.py cc-search nytimes.com --limit 5
  2. 검색 결과에서 WARC 파일(웹 아카이브)의 위치(offset, length)를 받음
  3. Range 요청으로 해당 부분만 정확히 다운로드 (전체 파일은 수 GB지만 필요한 건 수 KB)
  4. WARC에서 HTML 추출 → trafilatura로 본문 추출
NYT(뉴욕타임즈) 결론: NYT는 서버 사이드 페이월이라서 스텔스/VPN/headless 어떤 기술을 써도 전문을 못 가져와요 (구독 결제가 필요). Common Crawl에서는 2019~2020년 기사만 전문이 있고, 최근 기사는 robots.txt로 차단돼 있어요.

11. CLI 명령어 모음

main.py에서 쓸 수 있는 명령어들이에요:

명령어설명예시

export DB를 CSV/JSONL 파일로 내보내기 python main.py export --format csv
stats DB 현황 보기 python main.py stats
cc-search Common Crawl에서 도메인 검색 python main.py cc-search nytimes.com

14. 발표 Q&A 대비

Q. "범용"이라고 했는데 정말 아무 사이트나 되나요?

대부분의 한국 뉴스 사이트에서 작동해요. add-site 도메인으로 추가하면 RSS, 사이트맵, 목록 페이지 중 하나 이상을 자동으로 찾아서 수집 경로를 만들어요. 다만 로그인이 필수인 사이트나 서버 사이드 페이월(NYT 같은)은 기술적으로 우회할 수 없어요.

Q. 법적으로 문제 없나요?

robots.txt를 존중하고, 요청 간격을 두고, 과도한 부하를 주지 않아요. 수집한 데이터는 학습/연구 목적으로만 사용하고, 상업적 재배포는 하지 않아요. 저작권법상 "공정 이용"의 범위 내에서 운용해요.

Q. 왜 Selenium 대신 Playwright를 썼나요?

Playwright가 Selenium보다 빠르고, 안정적이고, 설정이 간단해요. 자동 대기(auto-wait) 기능이 내장되어 있고, Microsoft가 관리해서 업데이트가 빨라요. Selenium은 ChromeDriver 버전 맞추기가 번거로운 반면, Playwright는 playwright install chromium 한 줄이면 끝이에요.

Q. 데이터가 얼마나 정확한가요?

5단계 폴백 추출 시스템 덕분에 대부분의 사이트에서 80자 이상의 본문을 추출해요. 메타데이터(제목, 날짜, 기자)는 HTML meta 태그, JSON-LD, 본문 바이라인에서 보완하고, 같은 사이트 내 동일 내용은 text_hash로 중복을 걸러요.

Q. 스텔스 적용하면 100% 안 들키나요?

아니요. 스텔스는 기본적인 봇 탐지를 우회하는 거지, 완벽한 건 아니에요. Cloudflare, DataDome 같은 전문 보안 서비스는 마우스 움직임, 스크롤 패턴, TLS 지문 등 더 정교한 방법으로 탐지할 수 있어요. 그래서 차단 감지 + 24시간 쿨다운으로 차단당했을 때의 대응책도 같이 갖고 있어요.

Q. 이 프로젝트에서 가장 어려웠던 점은?

"범용"을 달성하는 것이 가장 어려웠어요. 뉴스 사이트마다 HTML 구조, 인코딩(UTF-8, EUC-KR), JS 렌더링 여부, 봇 방어 수준이 전부 달라서 하나의 코드로 모든 사이트를 처리하려면 예외 상황을 최대한 많이 고려해야 했어요. 특히 SBS처럼 자바스크립트로만 기사를 로드하는 사이트는 Playwright를 따로 붙여야 했고, 스텔스까지 적용해야 했어요.

Q. 확장 가능한가요? 해외 사이트도?

구조 자체는 언어 불문이에요. add-site guardian.com으로 해외 사이트도 추가 가능해요. 다만 한국어 바이라인 추출 정규식 등 일부 한국어 특화 로직이 있어서, 해외 사이트에 본격 적용하려면 그 부분만 다국어 지원으로 확장하면 돼요. Guardian은 별도 무료 API도 있어서 더 쉽게 가능해요.
