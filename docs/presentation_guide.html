01무엇을 하는 프로그램인가

비유. 전국 신문사 244곳에 매일 들러서 새 기사를 받아 오는 배달 로봇입니다. 보통 로봇은 신문사마다 "이 집은 문이 어디, 우편함이 어디"를 사람이 일일이 가르쳐야 합니다. 우리 로봇은 신문사 주소만 주면 처음 가서 스스로 집 구조를 파악하고 메모해 둡니다. 다음부터는 그 메모만 보고 다닙니다.

과제의 핵심 요구는 하나였습니다. "새 사이트를 등록할 때 코드를 고치지 않아도 바로 작동할 것." 보통 크롤러는 사이트마다 전용 코드를 짭니다. 우리는 반대로, 사이트를 관찰해서 설정 파일(sites.yaml)을 자동으로 쓰는 쪽을 택했습니다.

그래서 사용자가 치는 명령은 두 가지뿐입니다.

python main.py add-site hani.co.kr      # 신문사 등록: 조사해서 설정 파일에 적는다
python main.py crawl                    # 등록된 모든 신문사에서 새 기사를 받아 저장한다

crawler/discover.py

crawler/sources.py

기사 주소 모으기

메모를 보고 RSS → 뉴스 사이트맵 → 목록 페이지 순서로 기사 주소를 모읍니다. 앞 방법이 통하면 뒤 방법은 안 씁니다.

crawler/pipeline.py

배달 계획

이미 받은 주소는 빼고, robots.txt가 금지한 주소는 건너뛰고, 사이트마다 간격을 지키며 받아서 저장까지 이어 줍니다. 사이트끼리는 동시에, 한 사이트 안에서는 차례로.

crawler/storage.py

03사이트 등록 흐름: 처음 가는 집 파악하기

비유. 처음 가는 도서관에서 책 찾는 순서와 같습니다. 안내문을 읽고, 신간 목록표를 찾고, 전체 장서 목록을 찾고, 책 번호 규칙을 알아낸 뒤, 그 규칙으로 책 한 권을 실제로 꺼내 봅니다.

  1. robots.txt 읽기"지도는 여기 있어요", "천천히 와 주세요(Crawl-delay)" 같은 사이트의 안내문. 금지한 길은 끝까지 안 들어갑니다.
  2. RSS 찾기새 기사 목록표. 페이지 안의 링크, 한국 신문사들이 자주 쓰는 주소 14가지, RSS 안내 페이지까지 뒤지고, 찾은 건 실제로 열어 기사 목록이 들어 있는지 확인합니다.
  3. 사이트맵 찾기기사 전체 목록. robots에 적힌 것과 흔한 주소 8가지를 시험하고, 뉴스 전용 사이트맵은 따로 표시합니다.
  4. 기사 주소 규칙 만들기기사 주소 수십 개를 모아 공통 꼴을 뽑습니다. 숫자 ID 자리는 "숫자 아무거나(\d+)", 분야 이름 자리는 "글자 아무거나([^/]+)"로 바꿉니다. 예: 한겨레는 arti/분야/세부/숫자.html.
  5. 규칙 검증그 규칙에 맞는 기사 하나를 실제로 받아서 긴 문단과 날짜가 나오는지 봅니다. 목록 페이지가 기사로 둔갑하는 걸 막는 장치입니다. 통과한 것만 설정 파일에 적습니다.

추출기가 여섯 개인 이유

사이트마다 HTML 생김새가 달라서 한 가지 방법으로는 다 못 읽습니다. 앞 방법이 본문 200자를 못 채우면 다음 방법을 시도하고, 전부 짧으면 가장 긴 결과를 씁니다. 순서는 trafilatura(정밀) → JSON-LD → HTML 속 JSON(embedded) → trafilatura(재현율) → readability → newspaper4k입니다. 196곳 평가에서 189곳은 첫 단계에서 끝났고, 나머지가 뒤 단계로 살았습니다.

06예의와 안전장치: 길에서 지켜야 할 규칙

왜 중요한가. 크롤러가 예의 없이 두드리면 사이트가 문을 닫습니다. 실제로 하루에 전체 조사를 세 번 반복했다가 같은 호스팅을 쓰는 20곳이 하루 반 동안 우리를 막았습니다. 그 뒤로 규칙을 코드에 박았습니다.

규칙구현비유
robots.txt 준수금지 경로는 건너뛰고 셈. Crawl-delay가 있으면 그만큼 기다림"출입금지" 표지판 지키기
요청 간격같은 사이트 안에서 1초 이상, 자동 조사도 0.4초 이상문을 연달아 두드리지 않기
차단 감지403·429·봇 검사 페이지(Datadome, Cloudflare 등)를 응답에서 알아봄. 429는 재시도 안 함"지금은 안 돼요" 소리 듣기
즉시 중단 + 쿨다운차단이 보이면 그 사이트에 바로 멈추고 DB에 24시간 쿨다운을 적어 다음 실행에서도 건너뜀혼났으면 하루 쉬기
죽은 사이트 포기연결 오류 2회 연속이면 그 사이트는 이번엔 포기안 열리는 문 계속 밀지 않기
상한선요청 하나 45초·5MB, 사이트 하나 240초, 한 번 실행에 사이트당 새 기사 30건(조정 가능)한 집에서 너무 오래 머물지 않기

단순 403은 특정 주소만 막힌 걸 수도 있어서 연속 2회(자동 조사는 3회)일 때만 차단으로 봅니다. 한국경제 프리미엄 기사 하나 때문에 사이트 전체를 막지 않기 위해서입니다.

08한계와 실패 (정직하게 말할 것)

자바스크립트로만 그리는 사이트 4곳

SBS Biz, SBS연예뉴스, 스타뉴스, Arirang TV는 본문과 링크를 HTML이 아닌 별도 요청으로 받아 옵니다. 진짜 브라우저(Playwright)가 필요합니다. 설치는 했고 연결은 다음 단계입니다.

봇 차단 사이트

매일경제(Cloudflare), 뉴욕타임스(Datadome)는 브라우저 지문을 보고 거릅니다. 뚫으려 하면 IP 차단으로 번지고 약관 문제도 있어 대상에서 뺐습니다.

robots.txt가 전부 금지한 7곳

EBS, KBS World, MBC, TJB, 동아사이언스, 아시아경제, 톱데일리. 기술적으로는 받을 수 있지만 받지 않습니다.

부분 유료 기사

식품저널의 시장 보고서 시리즈, 시사IN 일부 기사는 앞부분만 저장됩니다. 로그인은 대신하지 않습니다.

처음에 저지른 실수들

CSS·이미지·목록 페이지를 기사로 고른 적이 18곳 있었고, 사이드바의 "많이 본 기사" 목록을 본문으로 집은 적도 있습니다. 둘 다 검증 규칙을 추가해 고쳤고 문서에 남겼습니다.

클라이언트 측 계량은 안 보임

뉴욕타임스처럼 브라우저 안에서 세는 페이월은 정적 요청으로는 확인할 수 없습니다. "계량 0곳"은 서버 쪽에서 막는 계량이 없다는 뜻입니다.

09발표 포인트와 예상 질문

꼭 말할 다섯 가지

  1. 문제 정의사이트마다 코드를 짜면 100곳이면 100벌. 우리는 "관찰해서 설정을 쓰는" 방식으로 바꿨다.
  2. 증명보류해 둔 20곳을 코드 수정 없이 한 줄씩 추가해 20/20 작동. 바뀐 파일은 sites.yaml 하나.
  3. 검증 중심찾은 RSS는 실제로 열어 보고, 기사 규칙은 기사 하나를 진짜 뽑아 본 뒤에만 채택. LLM 제안도 같은 검증을 거친다.
  4. 예의와 안전robots.txt, 요청 간격, 차단 감지와 24시간 쿨다운. 실제로 차단당한 경험에서 나온 설계.
  5. 정직한 한계JS 사이트 4곳, 봇 차단 2곳, robots 금지 7곳은 못 하거나 안 한다. 숫자로 말한다.

예상 질문

Q. 그냥 네이버 뉴스를 긁으면 더 쉽지 않나요?

쉽습니다. 하지만 과제는 "범용 뉴스 크롤러"였고, 네이버 뉴스는 한 사이트입니다. 한국어 오픈소스 대부분이 네이버 전용인 것도 확인했습니다. 우리는 언론사 사이트 244곳을 직접 다룹니다.

Q. 기사 주소 규칙을 어떻게 사람 없이 만드나요?

RSS나 사이트맵에서 기사 주소 수십 개를 모아 공통 꼴을 뽑습니다. 숫자 ID 자리는 \d+, 분야 이름 자리는 [^/]+로 일반화하고, 그 규칙에 맞는 기사 하나를 실제로 받아 긴 문단과 날짜가 나와야 채택합니다.

Q. 같은 기사가 두 번 저장되지 않나요?

주소가 같으면 안 넣고, 주소가 달라도 본문 글자를 정리해 만든 해시가 같으면 같은 사이트 안에서는 중복으로 봅니다. 시연 때 2,027건 중 28건이 그렇게 걸러졌습니다.

Q. 사이트에 피해를 주지 않나요?

같은 사이트엔 1초 이상 간격, robots.txt의 금지 경로와 Crawl-delay 준수, 차단 응답이 오면 즉시 멈추고 24시간 쉽니다. 한 번 실행에 사이트당 새 기사 30건이 기본 상한입니다.

Q. LLM은 어디에 쓰였나요?

자동 조사가 아무것도 못 찾은 사이트에서만, 페이지의 링크 목록 같은 증거를 보내 기사 주소 규칙을 제안받습니다. 제안은 실제 링크에 3개 이상 맞고 기사 추출이 되는 것만 채택합니다. 자격 증명이 있는 환경에서 실호출 시험이 남아 있습니다.

Q. 뉴욕타임스 같은 해외 사이트도 되나요?

뉴욕타임스는 기사 첫 요청부터 봇 검사(Datadome)에 막혔고 약관도 자동 수집을 금지합니다. 공식 RSS의 제목·요약까지만 가능하고 본문은 대상에서 뺐습니다.

10용어 사전

크롤러
웹 페이지를 자동으로 돌며 내용을 모으는 프로그램. 배달 로봇.
RSS
사이트가 내놓는 "새 글 목록표". 제목·링크·날짜가 기계가 읽기 좋은 꼴로 들어 있다.
사이트맵
사이트의 모든 페이지 주소를 적은 목록. 뉴스 전용 사이트맵은 최근 기사만 담는다.
robots.txt
사이트가 로봇에게 "여긴 와도 되고 저긴 안 돼"라고 적어 둔 안내문.
정규식
글자 패턴을 적는 방법. \d+는 "숫자 아무거나", [^/]+는 "슬래시 빼고 아무 글자".
JSON
데이터를 중괄호와 따옴표로 적는 형식. 자바스크립트 사이트가 본문을 이 안에 숨겨 두기도 한다.
SQLite
파일 하나로 되는 작은 데이터베이스. 설치 없이 쓸 수 있어 창고로 썼다.
인코딩
글자를 숫자로 저장하는 규칙. 한국 사이트는 UTF-8과 EUC-KR이 섞여 있어 잘못 읽으면 한글이 깨진다.
페이월
돈을 내거나 로그인해야 기사를 보여 주는 벽. "몇 건 읽으면 막는" 계량형과 "특정 기사만 잠그는" 부분형이 있다.
봇 차단
사이트가 "사람이 아닌 프로그램"을 알아보고 막는 것. Datadome, Cloudflare 같은 업체 서비스가 많다.
Playwright
코드로 조종하는 진짜 크롬. 자바스크립트가 그린 화면까지 읽을 수 있지만 느리고 무겁다.
LLM
Claude 같은 대형 언어 모델. 여기서는 사람이 할 "이 사이트 기사 주소 규칙 추측"을 대신하고, 결과는 코드가 검증한다.
